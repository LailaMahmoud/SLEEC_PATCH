# BSN status under the paper methodology

The previous claim of three deterministic BSN repairs and one corrected-BSN
repair is **withdrawn from the paper-method results**. Those candidates were
generated by `concern_completion`, an added deterministic operator outside the
generation split in Section III.B. That operator has been removed.

Changes remain local on `improvement/pipeline-robustness`. Nothing has been
deployed. Experimental inputs are unchanged.

Zero generated candidates is a limitation of the current deterministic
implementation for these diagnoses; it is not a proof that every possible
syntactic repair is impossible. New-rule generation belongs to the LLM stage.
Only a proposal obtained from that stage, parsed and formally verified, may
count as an LLM-assisted repair result.

The offline integration tests supply explicit handwritten model responses.
They demonstrate that source-anchored proposals can pass through the pipeline
and that incompatible proposals are rejected. They do not establish actual
model success on BSN. Grammar-safe rendering converts the fields supplied by
the model into SLEEC; it does not synthesize a replacement answer itself.

## Robustness fixes retained

- Diagnosis context preserves trace events, timestamps, measure values and
  affected rule IDs. Related responses inside exceptions are found without
  treating an unrelated rule as the edit target.
- Structured LLM proposals may reference a diagnosed source concern even when
  no existing rule is a suitable edit target. All original rules and
  verification requirements remain intact when adding a rule.
- Formal acceptance requires successful parsing, completion of all five
  detectors, removal of the selected issue and no new findings. A changed
  witness for the same source issue does not count as a repair.
- The situational checker binds trigger conditions to the correct timestamp,
  checks missing responses after finite deadlines, preserves interval bounds,
  and distinguishes explicit unbounded windows from finite or symbolic ones.
- Retired concern-completion candidates cannot be applied, ranked or exported.
  Failed or empty LLM responses cannot trigger deterministic additions.

These fixes correct implementation behavior without adding the withdrawn
repair operator to the methodology. Formal acceptance still does not establish
stakeholder agreement or operational feasibility. The normalizer's existing
finite representative horizon for blocking search remains a limitation.
